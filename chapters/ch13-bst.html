PART IV · 필요한 연산만 빠르게

Chapter 13. Binary Search Tree — 비교 한 번으로 탐색 공간을 줄인다

Set의 key 순서를 트리의 공간 배치로 바꾸면 검색과 순서 질의를 같은 길의 탐색으로 푼다.

학습목표

  • Set interface를 BST ordering invariant로 구현한다.
  • search/insert/delete/min/max/predecessor/successor를 추적한다.
  • 모든 비용이 높이 h에 달린 이유를 설명한다.

오늘의 문제

동적으로 변하는 key 집합에서 정확 검색뿐 아니라 최소·최대·직전·직후 key도 구하라.

Naive baseline

비정렬 배열은 삽입 Θ(1), 순서 질의 Θ(n). 정렬 배열은 binary search Θ(log n)이지만 중간 삽입·삭제가 Θ(n). Hash table은 기대 exact search는 빠르지만 순서를 잃는다.

병목

정렬 배열의 순서는 좋지만 원소 이동이 비싸다. 비교 결과를 왼쪽/오른쪽 링크로 저장하면 이동 없이 정렬 관계를 유지한다.

아이디어 재발명

        8
      /   \
     3     10
    / \      \
   1   6      14

노드 x마다 왼쪽 subtree key < x.key < 오른쪽 subtree key. 한 번 비교할 때 한 subtree를 버린다. 단, 버려지는 비율은 균형에 달렸다.

MIT formalization

find(k)는 root에서 시작해 같으면 종료, 작으면 left, 크면 right로 간다. insert는 실패한 탐색 위치에 leaf를 붙인다. min/max는 끝까지 left/right. successor는 오른쪽 subtree의 min, 없다면 처음으로 현재 노드가 왼쪽 자식이 되는 ancestor다. predecessor는 대칭이다. 두 자식이 있는 delete는 successor와 위치를 바꾼 뒤 자식 ≤1인 노드 삭제로 줄인다.

WHY?

한 경로만 방문하므로 연산량은 방문 가능한 가장 긴 root-to-leaf 경로 h에 비례한다.

INVARIANT

모든 노드 x에서 left subtree의 모든 key는 x보다 작고 right subtree의 모든 key는 x보다 크다.

TRADE-OFF

순서를 보존해 predecessor/range traversal을 얻지만 pointer 공간을 쓰고, 균형을 보장하지 않으면 h가 n까지 커진다.

DON’T USE THIS WHEN

exact-key lookup만 필요하고 기대 O(1)이 적합하거나, 메모리 지역성과 단순한 정적 binary search가 더 중요한 경우.

손으로 추적하기

8,3,10,1,6,14 삽입 뒤 6 검색 경로는 8→3→6. min=1, max=14, predecessor(8)=6, successor(8)=10. 3 삭제는 successor 6으로 대체한 뒤 원래 6 leaf를 제거한다.

Python 의사코드

def find(root, key):
    node = root
    while node and node.key != key:
        node = node.left if key < node.key else node.right
    return node

def insert(root, item):
    parent, node = None, root
    while node:
        parent, node = node, node.left if item.key < node.key else node.right
    # parent의 알맞은 빈 링크에 item을 leaf로 연결한다.

def delete(node):
    if node.left and node.right:
        swap_items(node, minimum(node.right))
        node = minimum(node.right)
    replace_with_child(node)  # 자식이 0개 또는 1개

Correctness와 핵심 불변식

탐색에서 k<x.key이면 invariant상 k는 right subtree에 없으므로 left만 가도 안전하다. 삽입은 비교 경로 끝의 유일한 합법 위치에 붙인다. 삭제의 successor는 x보다 큰 key 중 최소라 x 위치에 와도 양쪽 부등식을 보존한다.

Complexity

연산시간핵심 경로
search/insert/deleteO(h)root-to-node
min/maxO(h)left/right spine
predecessor/successorO(h)subtree 또는 ancestors
정렬 순회Θ(n)in-order

MIT-style 문제

Mechanics

5,2,8,1,4,7,9를 삽입해 그리고 5를 삭제하라.

Recognition

오름차순 key 삽입이 비용에 미치는 영향을 설명하라.

Invention

[a,b]의 모든 key를 출력하는 알고리즘과 출력 민감 비용을 제시하라.

해설 보기
  1. 5의 successor 7을 올리고 원래 7을 제거한다.
  2. 트리가 linked list처럼 되어 h=n-1, 연속 삽입 총 Θ(n²).
  3. a의 lower bound를 O(h)에 찾고 successor를 따라 k개 출력해 O(h+k).

Feynman Test

BST 연산이 왜 O(log n)이 아니라 O(h)라고 먼저 말해야 하는지 설명하라.

빈 종이 테스트

ordering invariant, 7개 Set 연산의 경로, 세 가지 delete 경우를 복원하라.

한 장 요약

  • BST는 key 순서를 링크에 저장하는 Set 구현이다.
  • 모든 단일 연산은 O(h), in-order traversal은 Θ(n).
  • h=Θ(log n)을 별도로 보장해야 진짜 logarithmic Set이 된다.
