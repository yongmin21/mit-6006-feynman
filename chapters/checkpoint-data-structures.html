CHECKPOINT · CHAPTER 3–6, 12–16

Data Structures Design Checkpoint

자료구조 이름부터 말하지 않는다. 워크로드를 세고 필요한 interface를 정한 뒤 구현을 선택한다.

사용법과 학습목표

  1. 75분 동안 외부 자료 없이 푼다.
  2. 각 답에 workload, interface, invariant, complexity를 쓴다.
  3. 그 뒤에만 해설을 펼친다.

MIT 문제 원문을 복제하지 않고 설계·분석 목표를 한국어 문제로 재구성했다.

1구역 · 연산표 완성

1. Sequence 구현

Array, Linked List, Dynamic Array의 get_at, first insert, last insert, known-node delete 비용을 표로 완성하라.

해설 보기
구조get_atfirst insertlast insertknown-node delete
ArrayΘ(1)Θ(n)Θ(n)Θ(n)
Linked ListΘ(n)Θ(1)Θ(1), tail 보유Θ(1), 필요한 링크 보유
Dynamic ArrayΘ(1)Θ(n)분할상환 Θ(1)Θ(n)

2. Set와 Priority Queue

Hash, plain BST, AVL, max-heap의 find/insert/delete/max/predecessor 비용과 보장 종류를 써라.

해설 보기

Hash exact 연산은 α=O(1)에서 기대 O(1), 순서 연산 Θ(n). BST는 O(h). AVL Set 연산은 최악 O(log n). Heap은 max Θ(1), insert/delete_max O(log n), 임의 find·predecessor Θ(n).

2구역 · 자료구조 선택

3. 세 workload

(a) ID exact lookup, (b) 동적 가격 predecessor/range, (c) 최고 priority pop에 최소 interface와 구조를 골라라.

해설 보기

(a) Dynamic Set→hash. (b) Ordered Set→AVL, range O(log n+k). (c) Priority Queue→max-heap.

4. 복합 workload

시간순 append, ID lookup, 최근 100건 순회가 필요한 로그 저장소를 설계하라.

해설 보기

Dynamic Array와 ID→위치 hash index. append 분할상환 기대 O(1), lookup 기대 O(1), 최근 조회 Θ(100). 두 구조가 같은 live record를 가리키는 것이 invariant다.

5. 문장 고치기

“Hash는 항상 O(1), BST는 O(log n), heap은 정렬되어 있다”를 정확히 고쳐라.

해설 보기

Hash는 조건부 기대 O(1), 최악 Θ(n). Plain BST는 O(h), AVL이어야 최악 O(log n). Heap은 parent-child 부분 순서만 있다.

3구역 · Invariant와 실패조건

6. 불변식 매칭

Hash, BST, AVL, augmented tree, heap의 핵심 invariant와 깨졌을 때의 오답을 연결하라.

해설 보기
  • Hash: x∈T[h(x.key)] — 검색 누락.
  • BST: left<x<right — 잘못된 가지 제거.
  • AVL: 정확한 height, |balance|≤1 — 선형 높이.
  • Augmentation: metadata=f(item, children) — 틀린 rank/aggregate.
  • Heap: parent≥children, complete shape — max/index 오류.

7. 경계 입력

모든 hash key 충돌, BST 정렬 삽입, dynamic array resize 한 번, AVL delete, heap 임의 검색의 비용을 써라.

해설 보기

각각 Θ(n), h=Θ(n), Θ(n) 복사, root까지 O(log n) 재균형, Θ(n) 검색. 분할상환·기대 보장은 한 연산의 최악을 지우지 않는다.

8. 회전 검증

AVL rotation 뒤 무엇을 어떤 순서로 다시 계산하는가?

해설 보기

링크 변경 뒤 아래 노드부터 height와 모든 augmentation을 부모 방향으로 갱신한다. Ordering만 맞아도 stale metadata는 이후 답을 틀리게 한다.

4구역 · Augmentation 설계

9. k번째와 구간 합

동적 key-value Set에서 k번째 key와 [a,b] value 합을 O(log n)에 답하도록 설계하라.

해설 보기

AVL에 size=1+L.size+R.size, sum=value+L.sum+R.sum. Select는 left size, range는 두 prefix sum. 갱신·회전 뒤 아래에서 위로 재계산.

10. 잘못된 요약

두 subtree의 median만으로 합친 subtree median을 O(1)에 구할 수 있는가?

해설 보기

불가능하다. 분포를 잃는다. Median을 저장하는 대신 결합 가능한 subtree_size로 order-statistic 탐색을 한다.

11. Materialized aggregate

Raw event 외에 일별 sum/count를 저장하는 설계와 augmentation의 공통점·실패조건을 쓰라.

해설 보기

읽을 답 일부를 미리 저장하고 write 때 갱신한다. 누락·중복 event, 비원자적 update, backfill 뒤 stale aggregate를 막거나 재계산해야 한다.

5구역 · 종합 설계

12. 배송 스케줄러

Job ID 취소, 가장 이른 deadline 실행, deadline 순위, 시간 구간 비용 합을 지원하라.

해설 보기

Deadline AVL에 size/sum을 두고 ID→node hash index를 함께 둔다. ID lookup 기대 O(1), 삭제·earliest·rank·range O(log n). 두 구조의 live job 집합이 같아야 한다. Rank/range가 드물면 min-heap+hash가 더 단순하다.

Feynman Test

12번 답을 구조 이름 없이 workload → interface → invariant → 비용 → 실패조건 순서로 설명하라.

빈 종이 테스트

Sequence/Set/Priority Queue 연산표와 Hash/BST/AVL/Augmentation/Heap invariant를 한 장에 복원하라.

한 장 요약

  • 빈번한 연산과 필요한 보장을 먼저 센다.
  • 그 연산만 제공하는 가장 작은 interface와 구조를 고른다.
  • 복합 index에는 동기화 비용이 있다.
  • 기대·분할상환·최악을 섞어 말하지 않는다.

다음 장 연결

Min-heap Priority Queue는 이후 Dijkstra에서 다음 정점을 고르는 핵심 도구가 된다.
