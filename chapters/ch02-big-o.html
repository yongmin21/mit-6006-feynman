Chapter 2. Big-O는 속도를 재는 단위가 아니다

Big-O는 몇 초가 걸리는지 말하지 않는다. 입력이 커질 때 비용이 어떻게 자라는지 설명한다.

오늘의 문제

같은 목록에서 이름을 찾는 두 프로그램이 있다. A는 노트북에서 2초, B는 휴대폰에서 1초가 걸렸다. B의 알고리즘이 더 좋다고 결론 내려도 될까?

아니다. 기기, 언어, 데이터와 구현이 모두 다르다. 비교하려면 같은 기본 연산을 몇 번 수행하는지 입력 크기 n의 함수로 적어야 한다.

WHY?

벽시계 시간은 환경을 측정하고, 점근 표기는 확장되는 모양을 측정한다. 그래서 아직 사지 않은 컴퓨터에서도 큰 입력의 경향을 말할 수 있다.

상수와 작은 항을 내려놓기

어떤 알고리즘의 연산 수가 3n² + 20n + 7이라고 하자. n이 충분히 커지면 n² 항이 증가를 지배한다.

3n² + 20n + 7 = Θ(n²)

상수가 현실에서 사라진다는 뜻은 아니다. 작은 입력에서는 상수와 구현 품질이 승패를 바꾼다. 점근 분석은 큰 입력에서 성장률을 비교하기 위한 렌즈다.

O, Ω, Θ를 한 문장씩

표기뜻직관
O(g(n))충분히 큰 n에서 위쪽 경계이보다 빠르게 자라지 않는다
Ω(g(n))충분히 큰 n에서 아래쪽 경계적어도 이만큼 자란다
Θ(g(n))위·아래 경계가 함께 맞음성장률이 이 정도다

2n + 10은 O(n²)이기도 하지만, 더 정확한 설명은 Θ(n)이다. Big-O만으로 “정확한 속도”를 말하려 하면 정보가 부족하다.

MENTAL MODEL

점근 표기는 함수들의 집합이다. O(n²)은 특정 시간값이 아니라, 충분히 큰 입력에서 어떤 상수배의 n² 아래에 머무는 모든 비용 함수를 가리킨다.

경우를 먼저 말하라

선형 탐색은 첫 원소가 답이면 Θ(1), 답이 마지막에 있거나 없으면 Θ(n)이다. “이 알고리즘은 O(n)”이라고만 말하기 전에 최악, 평균, 최선 중 무엇인지 밝혀야 한다.

  • 최악 경우: 보장해야 할 최대 비용
  • 최선 경우: 가장 운이 좋은 입력의 비용
  • 평균 경우: 입력 분포를 정의했을 때의 기대 비용

TRADE-OFF

Θ(n log n) 알고리즘이 아주 작은 n에서 Θ(n²) 알고리즘보다 느릴 수 있다. 입력 범위, 상수 비용, 메모리까지 보고 선택하되 성장률 차이는 입력이 커질수록 지배적이 된다.

DON’T USE THIS WHEN

Big-O 하나로 실제 지연 시간, 캐시 효과, 네트워크 대기, 에너지 사용량을 설명하려 하지 말자. 그런 질문에는 측정과 프로파일링이 필요하다.

예제: 두 정렬의 성장

# 삽입 정렬: 최악의 경우 비교 횟수가 n²에 비례
for i in range(1, n):
    for j in range(i, 0, -1):
        compare(j - 1, j)

# 병합 정렬: log n개 층마다 전체 n개를 처리
T(n) = 2T(n / 2) + Θ(n) = Θ(n log n)

코드는 다르지만 질문은 같다. 입력이 두 배가 될 때 지배적인 작업량은 어떻게 변하는가?

연습문제

  1. 7n + 500의 가장 타이트한 Θ 표기를 쓰라.
  2. n² + n log n에서 지배항은 무엇인가?
  3. 이진 탐색의 최선·최악 경우를 각각 설명하라.
  4. O(n) 알고리즘이 O(n²)이기도 한 이유와, 왜 보통 그렇게 부르지 않는지 설명하라.
해설 보기
  1. Θ(n).
  2. n²이므로 전체는 Θ(n²).
  3. 중간 원소가 답이면 Θ(1), 후보를 하나까지 줄이면 Θ(log n).
  4. n은 충분히 큰 n에서 n² 이하이므로 상한은 맞지만, Θ(n)이 더 많은 정보를 준다.

Feynman Test

“이 코드는 O(n)이니 1초 안에 끝난다”가 왜 틀린 말인가?

O와 Θ의 차이를 그래프 없이 설명할 수 있는가?

상수를 버리면서도 실제 성능에서 상수를 무시하면 안 되는 이유는?
