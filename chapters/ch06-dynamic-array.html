PART II · 자료를 담는 방식

Chapter 6. Dynamic Array — 미래를 위해 공간을 남겨둔다

매번 딱 맞게 만들지 않는다. 두 배의 여유를 사서 비싼 복사를 드물게 만든다.

학습목표

  • 길이와 용량을 구분하고 동적 배열의 불변식을 설명한다.
  • 기하급수적 확장이 append의 분할상환 Θ(1)을 만드는 이유를 계산한다.
  • 최악 한 번의 비용과 연산열 평균 비용을 구분한다.

오늘의 문제

최종 크기를 모르는 로그를 차례로 저장하면서 인덱스 접근은 Θ(1)로 유지하고 싶다. 매번 새 배열을 만들지 않고 어떻게 할까?

Brute force · 매번 정확한 크기로 복사

def append_exact(array, value):
    bigger = [None] * (len(array) + 1)
    for i, item in enumerate(array):
        bigger[i] = item
    bigger[-1] = value
    return bigger

k번째 append가 Θ(k)이므로 n번 비용은 1+2+…+n=Θ(n²)이다.

병목

공간이 한 칸 필요할 때마다 기존 원소 전체를 복사한다. 복사를 피할 수 없다면 복사 사이의 간격을 빠르게 늘려야 한다.

아이디어 재발명

배열이 꽉 찼을 때 한 칸이 아니라 용량을 두 배로 늘린다. 복사는 크기 1, 2, 4, 8, …에서만 일어난다.

1 + 2 + 4 + ··· + n/2 < n

n번 append 동안 복사한 원소는 2n보다 적고 새 값 쓰기 n번을 더해도 총 Θ(n), 연산당 분할상환 Θ(1)이다.

MIT formalization

동적 배열은 용량 capacity의 정적 배열과 실제 원소 수 length를 가진다. length < capacity면 끝 삽입은 한 칸 쓰기다. 같으면 더 큰 배열을 만들고 복사한다. 성장 인자 2는 용량이 기하급수적으로 커지게 한다.

WHY?

미리 남긴 빈칸은 낭비가 아니라 미래 append를 위한 선불 비용이다. 비싼 작업을 충분히 많은 싼 작업 사이에 퍼뜨린다.

INVARIANT

0 ≤ length ≤ capacity이고 유효한 원소는 저장소의 [0,length)에 순서대로 있다. [length,capacity)는 접근할 수 없는 여유 공간이다.

TRADE-OFF

append와 임의 접근은 빠르지만 사용하지 않는 용량을 허용한다. 성장 인자가 크면 복사는 줄고 빈 공간은 늘며, 작으면 그 반대다.

DON’T USE THIS WHEN

각 연산의 엄격한 최악 Θ(1) 지연이 필요하면 resize 한 번의 Θ(n)이 문제가 된다. 또한 앞·가운데 삽입은 여전히 Θ(n)이다.

Python 구현

class DynamicArray:
    def __init__(self):
        self.length, self.capacity = 0, 1
        self.data = [None]

    def append(self, value):
        if self.length == self.capacity:
            self.capacity *= 2
            bigger = [None] * self.capacity
            for i in range(self.length):
                bigger[i] = self.data[i]
            self.data = bigger
        self.data[self.length] = value
        self.length += 1

    def get_at(self, i):
        if not 0 <= i < self.length:
            raise IndexError(i)
        return self.data[i]

Correctness와 핵심 불변식

resize 전 유효 원소 [0,length)를 같은 인덱스로 복사하므로 값과 순서가 보존된다. 이후 새 값을 정확히 length 위치에 쓰고 length를 하나 늘린다. 따라서 모든 append 뒤에도 유효 구간과 용량 불변식이 유지된다.

연산최악분할상환

분할상환은 확률적 평균이 아니다. 어떤 n번의 append 연산열에도 총비용 Θ(n)을 보장한다.

MIT-style 문제

Mechanics

초기 용량 1에서 9개를 append할 때 resize 시점과 복사 수를 구하라.

Recognition

매번 용량을 10칸씩 늘리면 왜 append가 분할상환 Θ(1)이 아닌가?

Invention

삭제 후 축소한다면 매 append/delete마다 resize가 반복되는 진동을 어떻게 막을까?

해설 보기
  1. 길이 1,2,4,8에서 resize하고 1+2+4+8=15개를 복사한다.
  2. resize가 Θ(n)번마다 아니라 상수 10번마다 일어나 총 복사가 Θ(n²)이다.
  3. 가득 찰 때 2배 확장하되 사용량이 용량의 1/4 이하일 때만 절반으로 줄여 확장·축소 경계에 간격을 둔다.

Feynman Test

append 한 번이 Θ(n)인데도 왜 “append는 분할상환 Θ(1)”이라고 말할 수 있는가?

분할상환과 평균 경우가 다른 이유는 무엇인가?

빈 종이 테스트

길이/용량 그림, 1·2·4·8 복사열, 기하급수 합, 최악/분할상환 비용표를 복원하라.

한 장 요약

  • 동적 배열은 정적 배열 + 길이 + 용량이다.
  • 꽉 찰 때 두 배로 늘리면 n번 append의 총비용은 Θ(n).
  • append는 최악 Θ(n), 분할상환 Θ(1), 임의 접근은 Θ(1).
