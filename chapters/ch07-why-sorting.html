PART III · 순서를 만들어 문제를 푼다

Chapter 7. Sorting이 필요한 이유

정렬은 답이 아니라, 어려운 질문을 이웃·경계·인덱스 문제로 바꾸는 중간 표현이다.

학습목표

  • 정렬을 search, duplicate, nearest, rank, range 문제의 전처리로 설명한다.
  • 정렬 비용과 이후 질의 비용을 함께 비교한다.
  • 키와 레코드, 전체 순서와 동률 처리의 차이를 구분한다.

오늘의 문제

학생 점수 n개에 대해 “73점이 있는가?”, “중복 점수는?”, “77점과 가장 가까운 값은?”, “상위 10명은?”, “[60,80] 구간은?”을 반복해서 묻는다. 질문마다 처음부터 훑어야 할까?

Naive baseline · 질문마다 선형 탐색

한 번의 질의는 Θ(n), q번이면 Θ(nq)이다. 종류가 다른 질문마다 별도 로직도 필요하다.

def contains(values, target):
    return any(x == target for x in values)

def duplicates(values):
    return [x for i, x in enumerate(values) if x in values[:i]]

병목

순서가 없어서 후보를 버릴 근거가 없다. 중복은 떨어져 있고, 가까운 값과 범위의 경계도 보이지 않는다.

아이디어 재발명

한 번 정렬해 [12, 31, 31, 73, 81, 95]로 만들면 검색은 이진 탐색, 중복은 이웃 비교, nearest는 삽입 위치의 양옆, rank는 인덱스, range는 두 경계 사이가 된다.

질문정렬 후 모습질의
search후보 절반 제거Θ(log n)
duplicate같은 키가 인접전체 Θ(n)
nearest삽입점 양옆Θ(log n)
rank위치가 순위Θ(1)
range두 경계 사이가 연속Θ(log n+k)

MIT formalization

MIT의 Set 인터페이스에서 정렬 배열은 build에 Θ(n log n)을 쓰고 find, find_next, find_prev를 Θ(log n)에 제공한다. 즉 정렬은 반복 질의를 위한 자료구조 표현이다.

WHY?

정렬은 흩어진 관계를 위치 관계로 바꾼다. 문제를 이미 아는 이진 탐색·스캔으로 환원할 수 있다.

INVARIANT

모든 i<j에 대해 key(A[i]) ≤ key(A[j])이다. 이 한 문장이 후보 제거와 경계 탐색을 정당화한다.

TRADE-OFF

전처리 Θ(n log n)과 저장 공간을 지불한다. 질의가 한 번이면 선형 탐색이 더 싸고, 값이 자주 바뀌면 정렬 유지 비용도 든다.

DON’T USE THIS WHEN

단 한 번의 존재 확인, 입력이 계속 변하는데 순서 질의가 없는 경우, 해시로 충분한 정확 일치 검색에는 정렬이 과하다.

손으로 추적하기

[8,3,8,1,6]을 [1,3,6,8,8]로 정렬하라. 7의 삽입 위치는 3이고 nearest 후보는 6과 8, 중복은 마지막 두 8, [3,8]은 인덱스 1부터 5 직전까지다.

Python 구현

from bisect import bisect_left, bisect_right

def range_query(values, lo, hi):
    ordered = sorted(values)
    left = bisect_left(ordered, lo)
    right = bisect_right(ordered, hi)
    return ordered[left:right]

Correctness와 핵심 불변식

bisect_left 왼쪽은 모두 lo보다 작고, bisect_right 오른쪽은 모두 hi보다 크다. 정렬 불변식 때문에 그 사이에 있고 오직 그 사이에 있는 값만 범위 답이다.

Complexity

정렬 Θ(n log n) 뒤 q개의 범위 질의는 출력 크기 합을 K라 할 때 Θ(n log n+q log n+K)다. 매번 스캔하는 Θ(nq)와 워크로드로 비교한다.

MIT-style 문제

Mechanics

정렬된 배열에서 42의 첫 위치와 마지막 다음 위치를 이진 탐색으로 표시하라.

Recognition

10만 개 고정 데이터에 범위 질의가 10만 번 온다. 선형 스캔과 정렬 전처리를 비교하라.

Invention

좌표 n개에서 가장 가까운 두 점의 거리를 구하는 1차원 알고리즘을 설계하라.

해설 보기
  1. lower/upper bound 두 경계를 찾는다.
  2. Θ(nq)보다 Θ(n log n+q log n+K)가 유리하다.
  3. 정렬 후 인접한 두 좌표의 차이만 검사하면 된다. 비인접 쌍 사이에는 더 가까운 인접 쌍이 존재한다.

Feynman Test

“정렬은 중간 표현이다”를 search와 range 예시로 60초 안에 설명하라.

빈 종이 테스트

다섯 문제를 적고 각각이 정렬 뒤 어떤 위치 문제로 바뀌는지, 전처리/질의 비용을 복원하라.

한 장 요약

  • 정렬은 값 관계를 위치 관계로 바꾼다.
  • 검색·중복·최근접·순위·범위가 단순해진다.
  • 정렬할지는 전체 워크로드 비용으로 결정한다.

다음 장 연결

중간 표현의 가치가 보였다. 이제 카드를 직접 정렬하며 가장 단순한 두 알고리즘과 안정성·제자리성의 의미를 만든다.
