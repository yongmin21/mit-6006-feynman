Chapter 11. Counting Sort / Radix Sort

키를 비교하지 말고 주소와 자릿값으로 사용하면 comparison lower bound의 문밖으로 나간다.

학습목표

  • key universe u와 n의 관계로 Counting Sort 비용을 분석한다.
  • stable Counting Sort를 자릿값별로 반복해 Radix Sort를 도출한다.
  • word-RAM 가정과 comparison lower bound를 피하는 이유를 설명한다.

오늘의 문제

0 이상 999,999 이하 학번 n개를 정렬한다. 모든 쌍의 대소 비교 없이 n에 가까운 시간에 할 수 있을까?

Naive baseline · Merge Sort

Θ(n log n)은 어떤 객체 키에도 안전하다. 하지만 정수 키의 제한된 범위와 자릿값이라는 추가 정보를 버린다.

병목

비교는 한 번에 두 갈래만 구분한다. word-RAM에서는 한 word 정수의 산술·인덱싱을 O(1)에 할 수 있으므로 키 자체를 버킷 주소로 쓸 수 있다.

아이디어 재발명

Counting Sort

count[k]에 키 k의 개수를 센 뒤 누적 개수로 출력 위치를 정한다. 시간과 공간은 Θ(n+u).

Radix Sort

큰 키를 base b의 자릿값으로 나누고 낮은 자리부터 stable sort한다. 한 패스 Θ(n+b), 자릿수 d=ceil(log_b u), 총 Θ(d(n+b)).

MIT formalization

키가 한 word에 들어가고 word 연산·임의 접근이 O(1)인 word-RAM을 가정한다. u=O(n)이면 Counting Sort는 Θ(n). 적절한 base로 Radix Sort는 다항식 크기 universe의 키도 선형에 가깝게 정렬한다.

WHY?

키로 배열 칸을 직접 고르면 한 연산이 두 갈래 비교보다 많은 경우를 구분한다. 따라서 comparison decision tree의 전제가 깨진다.

INVARIANT

Radix의 i번째 stable pass 뒤에는 원소가 하위 i개 자릿값을 기준으로 정렬되어 있다. 동률의 이전 순서를 보존해야 다음 자릿값이 기존 순서를 파괴하지 않는다.

TRADE-OFF

비교 횟수 대신 key universe, 자릿수, 보조 공간에 비용을 지불한다. 안정성은 Radix의 정확성 조건이다.

DON’T USE THIS WHEN

u가 n보다 지나치게 크거나 키가 O(1) word에 들지 않거나 임의 객체 비교만 가능하면 Merge Sort 같은 비교 정렬을 쓴다.

손으로 추적하기

[21,13,12,23]을 base 10 LSD Radix로 정렬한다. 일의 자리 stable pass: [21,12,13,23]. 십의 자리 pass: [12,13,21,23]. 첫 pass의 안정성이 12와 13의 순서를 보존한다.

Python 구현

def counting_sort(items, key, universe):
    buckets = [[] for _ in range(universe)]
    for item in items:
        buckets[key(item)].append(item)  # append 순서가 안정성 보존
    return [item for bucket in buckets for item in bucket]

def radix_sort(values, digits, base=10):
    out, place = list(values), 1
    for _ in range(digits):
        out = counting_sort(out, lambda x: (x // place) % base, base)
        place *= base
    return out

Correctness와 핵심 불변식

Counting은 키 순서대로 버킷을 이어 붙여 정렬되고 각 입력을 한 번 넣어 원소를 보존한다. Radix는 귀납적으로 하위 자리가 정렬되어 있다고 할 때 stable한 다음 pass가 같은 새 자릿값 안에서 그 순서를 유지한다. d회 후 전체 키가 정렬된다.

Complexity

알고리즘시간공간조건
CountingΘ(n+u)Θ(n+u)정수 키 [0,u)
RadixΘ(d(n+b))Θ(n+b)d자리, base b, stable pass
MergeΘ(n log n)Θ(n)비교 가능한 키

MIT-style 문제

Mechanics

[2A,1X,2B,0Z]를 stable Counting Sort하고 같은 키 레코드 순서를 확인하라.

Recognition

n=1,000인데 u=10¹²인 키에 직접 Counting Sort가 부적합한 이유는?

Invention

0≤k<n² 키를 base n Radix Sort로 정렬할 때 pass 수와 시간을 구하라.

해설 보기
  1. [0Z,1X,2A,2B]; 2A가 2B보다 앞선다.
  2. Θ(u) 초기화·공간이 입력보다 압도적으로 크다.
  3. 두 자리이므로 2 passes, 각 Θ(n+n), 총 Θ(n)이다.

Feynman Test

Counting Sort가 Ω(n log n)과 모순되지 않는 이유, Radix에서 stable이 필수인 이유를 설명하라.

빈 종이 테스트

n/u/b/d 기호, 두 비용식, word-RAM 가정, LSD 두 pass 추적을 복원하라.

한 장 요약

  • Counting은 키를 주소로 써 Θ(n+u).
  • Radix는 stable한 자릿값 정렬을 d번 해 Θ(d(n+b)).
  • 선형 정렬은 더 강한 계산 모델과 제한된 키 구조를 산다.
