PART III · 순서를 만들어 문제를 푼다

Chapter 10. Comparison Sorting의 한계

알고리즘 하나가 느린 것이 아니라, “비교만으로 알아내기” 자체에 필요한 질문 수가 있다.

학습목표

  • 비교 알고리즘 실행을 decision tree의 경로로 해석한다.
  • n!개 순열과 트리 높이로 Ω(n log n) 하한을 직관적으로 도출한다.
  • 하한의 적용 범위가 comparison model임을 분명히 말한다.

오늘의 문제

어떤 영리한 비교 순서를 쓰면 최악의 경우에도 n개를 o(n log n)에 정렬할 수 있을까?

Naive baseline · 더 영리한 비교 찾기

pivot, gap, 재귀 순서를 바꿔도 각 질문의 답이 “예/아니오”라면 한 비교가 구분하는 정보는 두 갈래뿐이다.

병목

서로 다른 n개 입력에는 가능한 순서가 n!개다. 올바른 알고리즘은 어느 순열인지 구별해야 한다.

아이디어 재발명

비교를 질문으로 그린다. 내부 노드는 a≤b?, 가지는 답, 잎은 최종 순서다. 높이 h인 이진 트리는 최대 2ʰ개 잎을 가지므로 2ʰ ≥ n!, 따라서 h ≥ log₂(n!) = Ω(n log n)이다.

a ≤ b?
예 ↙　　↘ 아니오
b ≤ c?　　 a ≤ c?
… 최소 3! = 6개 잎 필요

MIT formalization

결정적 comparison sort의 최악 비교 횟수는 결정 트리 높이다. n! ≥ (n/2)^(n/2)이므로 log₂(n!) ≥ (n/2)log₂(n/2)=Ω(n log n). Merge Sort의 O(n log n)과 만나 Θ(n log n)이 비교 모델에서 최적이다.

WHY?

하한은 특정 코드가 아니라 허용된 정보 획득 방식 전체를 제한한다. “비교만 한다”는 가정이 핵심이다.

INVARIANT

현재 노드에 도착한 입력들은 지금까지 같은 비교 결과를 냈다. 잎에서는 가능한 순서가 하나로 좁혀져야 한다.

TRADE-OFF

비교 모델은 임의 객체에 널리 적용되지만 키의 숫자 구조를 쓰지 않는다. 더 강한 연산을 허용하면 하한 밖으로 나갈 수 있다.

DON’T USE THIS WHEN

“모든 정렬은 Ω(n log n)”이라고 말하지 마라. 작은 정수 키를 인덱스로 쓰는 Counting/Radix Sort에는 이 결정 트리가 적용되지 않는다.

손으로 추적하기

세 원소는 6가지 순열이다. 깊이 2의 이진 트리는 잎이 최대 4개라 부족하고 깊이 3은 최대 8개라 가능하다. 따라서 어떤 비교 정렬도 최악에는 적어도 3번 비교한다.

의사코드 · 알고리즘을 트리로 읽기

compare(a, b)
├─ a ≤ b: compare(b, c)
│  ├─ b ≤ c: a, b, c
│  └─ b > c: compare(a, c) → ...
└─ a > b: compare(a, c) → ...

# 각 입력은 루트에서 정확한 순서의 잎까지 한 경로를 걷는다.

Correctness와 핵심 불변식

서로 다른 두 순열이 같은 잎에 도착하면 알고리즘은 둘에 같은 출력 순서를 내므로 적어도 하나는 틀린다. 따라서 n!개 순열에는 n!개 이상의 잎이 필요하고 높이 하한이 따라온다.

Complexity

log(n!)=Θ(n log n). 이는 최악 비교 횟수 하한이다. 입력 읽기 Ω(n)보다 강하며, Merge Sort의 상한과 정확히 맞는다.

MIT-style 문제

Mechanics

4개 원소에 필요한 잎 수와 최소 트리 높이의 하한을 구하라.

Recognition

키가 0 또는 1뿐인 배열을 Θ(n)에 정렬해도 하한과 모순이 아닌 이유를 설명하라.

Invention

비교 결과가 한 번에 세 갈래(<,=,>)라면 서로 다른 키 입력의 점근 하한이 바뀌는가?

해설 보기
  1. 24개 잎, 높이는 최소 ceil(log₂24)=5.
  2. 가능한 출력이 n!개가 아니며 키 값을 직접 분류할 수 있다.
  3. 3^h≥n!에서 h≥log₃(n!)=Ω(n log n)이라 상수만 바뀐다.

Feynman Test

“왜 n!인가?”, “왜 log인가?”, “왜 comparison이라는 단서가 필요한가?”를 그림 없이 설명하라.

빈 종이 테스트

결정 트리의 노드·가지·잎 대응과 2^h≥n!, log(n!)=Θ(n log n)을 복원하라.

한 장 요약

  • n!개 가능한 순서를 구별해야 한다.
  • 이진 비교 h번은 최대 2ʰ개 경우를 구별한다.
  • 비교 정렬 최악 하한은 Ω(n log n), 모델을 바꾸면 피할 수 있다.

다음 장 연결

정수 키의 자릿값과 배열 인덱스를 쓰면 한 질문이 두 갈래보다 많은 정보를 준다. 그 탈출구를 만든다.
