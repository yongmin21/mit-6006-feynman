PART IV · 필요한 연산만 빠르게

Chapter 16. Heap — 전체 순서를 알 필요는 없다

최댓값 하나만 반복해서 필요하면 모든 원소를 정렬하거나 완전한 Set을 만들 이유가 없다.

학습목표

  • priority queue interface를 구현보다 먼저 정의한다.
  • binary heap의 property·array representation·sift를 추적한다.
  • build-heap Θ(n), heapsort Θ(n log n), Dijkstra 연결을 설명한다.

오늘의 문제

작업이 계속 도착한다. 가장 높은 priority 작업을 반복해서 꺼내되 전체 정렬 순서는 요구하지 않는다.

Naive baseline

비정렬 배열은 insert Θ(1), delete_max Θ(n). 정렬 배열은 max Θ(1)이지만 insert Θ(n). AVL은 둘 다 O(log n)이지만 필요 없는 predecessor·range까지 제공한다.

병목

우리는 전체 순서가 아니라 root가 최댓값이라는 부분 순서만 필요하다. 필요한 interface는 build, insert, find_max, delete_max다.

아이디어 재발명

Complete binary tree를 level order array로 저장한다: left=2i+1, right=2i+2, parent=(i-1)//2. Max-heap property는 모든 parent key≥children key다. Insert는 끝에 append 후 sift-up, delete_max는 root와 마지막을 바꿔 pop한 뒤 sift-down한다.

array: [9, 7, 8, 2, 4, 3]
          9
       /     \
      7       8
     / \     /
    2   4   3

MIT formalization

Complete tree의 높이는 Θ(log n)이고 pointer 없이 array index로 이웃을 O(1)에 계산한다. max_heapify_down은 두 child 중 큰 쪽과 바꾸며 한 root-to-leaf 경로만 간다. Build-heap은 마지막 internal node부터 역순으로 sift-down한다.

WHY?

Heap property만으로 max가 root에 있다. 형제나 다른 subtree 사이의 순서는 몰라도 priority queue에는 충분하다.

INVARIANT

배열은 빈틈 없는 complete tree이고 모든 edge에서 parent priority≥child priority다. Sift 중에는 이동 경로 밖의 heap property가 유지된다.

TRADE-OFF

O(1) max와 O(log n) 갱신, 좋은 cache locality를 얻지만 임의 key search·predecessor는 Θ(n)이다.

DON’T USE THIS WHEN

exact-key lookup, 정렬 순회, range query가 핵심이거나 stable한 동률 순서가 별도 tie-breaker 없이 필요할 때.

손으로 추적하기

[9,7,8,2,4,3]에 10 삽입: 끝 index 6 → parent 8과 swap → parent 9와 swap, [10,7,9,2,4,3,8]. delete_max: 8을 root로 옮기고 큰 child 9와 swap, [9,7,8,2,4,3].

Python 구현

def sift_down(a, i, n):
    while 2 * i + 1 < n:
        child = 2 * i + 1
        if child + 1 < n and a[child + 1] > a[child]: child += 1
        if a[i] >= a[child]: break
        a[i], a[child] = a[child], a[i]
        i = child

def build_heap(a):
    for i in range(len(a) // 2 - 1, -1, -1): sift_down(a, i, len(a))

def heapsort(a):
    build_heap(a)
    for end in range(len(a) - 1, 0, -1):
        a[0], a[end] = a[end], a[0]
        sift_down(a, 0, end)
    return a

Correctness와 핵심 불변식

Sift-down 시작 시 root를 제외한 두 child subtree는 heap이다. 큰 child와 바꾸면 이전 root가 다른 child보다도 크므로 위 edge가 복구되고 위반 가능성은 아래 한 경로로만 이동한다. 종료하면 전체가 heap. Heapsort는 매 반복마다 suffix가 정렬된 최댓값들이고 prefix는 heap이라는 invariant를 유지한다.

Complexity

연산시간이유

insert/delete_maxO(log n)한 높이 경로

heapsortΘ(n log n)n회 delete_max 상당

왜 build-heap은 Θ(n)인가?

각 node마다 O(log n)이라 단순 곱하면 O(n log n)이지만, 절반은 leaf라 0, 1/4만 높이 1 이상, 1/8만 높이 2 이상이다. 합 n/4·1+n/8·2+…=Θ(n).

MIT-style 문제

Mechanics

[4,10,3,5,1]을 bottom-up max build-heap하고 배열을 써라.

Recognition

우선순위 작업 처리에 sorted array보다 heap이 나은 workload를 말하라.

Invention

min-heap에서 priority 감소 연산을 설계하고 Dijkstra에서 왜 필요한지 예고하라.

해설 보기
  1. 마지막 internal node부터 sift-down하여 한 결과는 [10,5,3,4,1].
  2. insert와 최고 우선순위 삭제가 반복되면 둘 다 O(log n)이고, 정렬 배열의 Θ(n) 삽입을 피한다.
  3. key를 줄인 뒤 parent보다 작으면 sift-up한다. Dijkstra는 더 짧은 경로를 발견할 때 vertex의 tentative distance를 낮춘다.

Feynman Test

Heap이 “정렬되지 않았는데도” max를 정확히 주는 이유와 build-heap이 선형인 이유를 설명하라.

빈 종이 테스트

세 index 식, sift-up/down, heap·heapsort invariant, build-heap 합을 복원하라.

한 장 요약

  • Priority queue는 전체 Set보다 작은 interface다.
  • Complete-tree array + heap property가 max와 갱신을 빠르게 한다.
  • 이 min-priority queue는 이후 Dijkstra의 다음 vertex 선택을 가속한다.
