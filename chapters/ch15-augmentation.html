PART IV · 필요한 연산만 빠르게

Chapter 15. Tree Augmentation — 미래의 답을 조금 저장해두기

매번 subtree를 다시 세지 말고, 자식의 요약으로 부모의 답을 O(1)에 유지한다.

학습목표

  • subtree_size로 select/rank를 설계한다.
  • sum/min/max metadata로 range aggregation을 도출한다.
  • query 이득과 update 유지 비용을 함께 판단한다.

오늘의 문제

동적 Set에서 “k번째 작은 key”, “이 key의 순위”, “[a,b] 값의 합”을 매번 전체 순회 없이 답하라.

Naive baseline

BST in-order traversal로 매 query마다 Θ(n)에 계산할 수 있다. AVL의 높이는 작지만 subtree 안의 개수나 합은 구조만 보고 알 수 없다.

병목

질의마다 같은 subtree를 다시 집계한다. 갱신 경로에 있는 O(log n)개 노드만 실제로 답이 바뀐다는 점을 이용한다.

아이디어 재발명

노드 x에 size=1+size(left)+size(right), sum=value+sum(left)+sum(right)를 저장한다. 필요하면 같은 패턴으로 subtree min/max도 둔다. k번째 원소는 left size L과 k를 비교해 left, x, right 중 하나만 간다.

MIT formalization

Augmentation은 subtree의 metadata를 자식 metadata와 현재 item으로 O(1)에 계산할 수 있어야 한다. insert/delete/rotation 뒤 바뀐 노드부터 ancestor 방향으로 다시 계산한다. AVL path 길이가 O(log n)이므로 기본 갱신의 점근 비용을 유지한다.

WHY?

query의 미래 답 일부를 각 subtree에 materialize해 한 비교마다 subtree 전체를 건너뛴다.

INVARIANT

모든 노드의 metadata는 현재 item과 두 자식의 metadata로 정의한 함수와 정확히 같다. 구조 변경 뒤 아래에서 위 순서로 갱신한다.

TRADE-OFF

질의를 빠르게 하는 대신 노드당 공간과 모든 갱신·회전의 metadata 유지 비용을 지불한다.

DON’T USE THIS WHEN

해당 집계 질의가 드물거나 aggregate가 자식 요약에서 O(1)에 결합되지 않거나, 원본 갱신과 metadata의 원자적 일관성을 보장할 수 없을 때.

손으로 추적하기

        8(size=6,sum=42)
       /                 \
 3(size=3,sum=10)    10(size=2,sum=24)
 / \                       \
1   6                       14

0-based select(2): root의 left size=3이므로 left로, 노드 3의 left size=1에서 k=2는 right로 바뀐 k=0, 답은 6. 8의 rank는 left size 3이다.

Python 의사코드

def update(x):
    x.size = 1 + size(x.left) + size(x.right)
    x.sum = x.value + total(x.left) + total(x.right)

def select(x, k):                 # 0-based
    left_n = size(x.left)
    if k < left_n: return select(x.left, k)
    if k == left_n: return x
    return select(x.right, k - left_n - 1)

def prefix_sum(x, key):           # node.key <= key
    if not x: return 0
    if key < x.key: return prefix_sum(x.left, key)
    return total(x.left) + x.value + prefix_sum(x.right, key)

def range_sum(root, a, b):
    return prefix_sum(root, b) - prefix_sum(root, a - 1)

Correctness와 핵심 불변식

Select는 BST 순서상 left의 L개가 먼저임을 이용해 정확히 한 영역으로 k를 변환한다. Prefix sum은 key<=x.key일 때 left 전체와 x를 안전하게 더하고 right만 재귀한다. Update 식을 구조 변경의 역순으로 적용하면 귀납적으로 모든 metadata가 정확하다.

데이터 엔지니어의 같은 패턴

DB index는 검색 경로를 저장하고, materialized aggregate는 반복 집계의 답을 미리 저장하며, cached metadata는 원본에서 파생된 작은 요약이다. 공통 질문은 “읽기가 얼마나 줄고, 쓰기 때 무엇을 갱신하며, 일관성을 어떻게 지킬까?”다.

MIT-style 문제

Mechanics

위 트리에 key 7, value 7을 넣고 바뀌는 size/sum을 표시하라.

Recognition

subtree 평균만 저장하는 설계가 결합하기 어려운 이유와 수정안을 말하라.

Invention

동적 점수 집합에서 중앙값과 [a,b] 합을 함께 지원할 metadata를 설계하라.

해설 보기
  1. 7,6,3,8 경로의 metadata만 아래에서 위로 갱신한다. root size=7, sum=49.
  2. 평균끼리는 가중치가 없어 결합 불가. sum과 count를 저장한다.
  3. size와 sum을 함께 저장한 AVL. median은 select, 범위합은 두 prefix sum으로 O(log n).

Feynman Test

Augmentation 후보가 좋은지 “결합 가능성·갱신 경로·질의 절감” 세 기준으로 설명하라.

빈 종이 테스트

size/sum update 식, select의 세 갈래, prefix sum 경로, rotation 뒤 갱신 순서를 복원하라.

한 장 요약

  • 자식 요약에서 O(1)에 부모 요약을 만들 수 있는 값을 저장한다.
  • AVL에서는 query와 update 모두 O(log n)을 유지할 수 있다.
  • 빠른 read는 추가 storage·write·consistency 비용과 교환된다.

다음 장 연결

모든 순서 연산이 아니라 “가장 우선인 하나”만 필요하면 더 단순한 heap이 충분하다.
