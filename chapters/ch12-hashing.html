PART IV · 필요한 연산만 빠르게

Chapter 12. Hashing — key에서 위치로 순간이동하기

비교하며 찾지 말고 key를 작은 배열의 주소로 바꾼다.

학습목표

  • direct access array에서 hashing을 재발명한다.
  • collision, chaining, load factor가 비용을 만드는 방식을 설명한다.
  • worst-case·expected·amortized를 구분하고 universal hashing의 보장을 말한다.

오늘의 문제

학생 ID로 레코드를 계속 삽입·검색·삭제한다. key 범위는 매우 크지만 실제 학생은 n명뿐이다.

Naive baseline

비정렬 배열은 공간 Θ(n)이지만 find가 Θ(n). Direct access array는 A[key]로 worst-case Θ(1)이지만 key universe u만큼 Θ(u) 공간을 쓴다.

병목

빈 key 주소를 모두 예약하는 낭비가 병목이다. m=Θ(n)칸만 만들고 h(key)로 [0,m)의 주소를 계산하면 공간을 줄일 수 있다.

아이디어 재발명

  1. Hash function: 큰 universe를 작은 table index로 압축한다.
  2. Collision: 서로 다른 key가 같은 칸에 올 수밖에 있다.
  3. Chaining: 각 칸에 충돌한 항목의 작은 목록을 둔다.
  4. Load factor: α=n/m는 평균 chain 길이이므로 m=Θ(n)을 유지한다.
  5. Universal hashing: 입력을 본 뒤 고정 함수를 공격하지 못하도록 함수 집합에서 무작위로 고른다.

MIT formalization

Universal family H는 임의의 서로 다른 key a,b에 대해 Pr[h(a)=h(b)] ≤ 1/m을 만족한다. 선택된 h에 대한 기대 chain 길이는 O(1+α). α=O(1)이면 find/insert/delete는 기대 O(1)이다. 그러나 한 실행의 최악에는 모든 key가 충돌해 Θ(n)일 수 있다.

WHY?

정렬된 배열의 Θ(log n) 비교 대신 word-RAM의 O(1) 주소 계산을 사용한다.

INVARIANT

모든 항목 x는 정확히 bucket T[h(x.key)]에 있고, 같은 key는 중복 저장하지 않는다.

TRADE-OFF

순서 연산을 포기하고 기대 상수 시간 exact-key 연산을 얻는다. resize 한 번은 Θ(n)이지만 기하급수 확장을 쓰면 갱신은 분할상환 기대 O(1)이다.

DON’T USE THIS WHEN

min/max, predecessor, 정렬 순회, range query가 핵심이거나 적대적 입력에서 엄격한 최악 시간 보장이 필요할 때.

손으로 추적하기

m=5, h(k)=k mod 5에서 12, 7, 18을 넣으면 bucket 2에 [12,7], bucket 3에 [18]이 된다. 7 검색은 bucket 2만 훑는다. 이 예의 나머지 함수는 직관용이며 universal 보장은 아니다.

Python 구현

class ChainHashSet:
    def __init__(self, m=8):
        self.buckets = [[] for _ in range(m)]

    def _bucket(self, key):
        return self.buckets[hash(key) % len(self.buckets)]

    def find(self, key):
        return next((x for x in self._bucket(key) if x[0] == key), None)

    def insert(self, key, value):
        bucket = self._bucket(key)
        for i, item in enumerate(bucket):
            if item[0] == key:
                bucket[i] = (key, value); return
        bucket.append((key, value))

    def delete(self, key):
        bucket = self._bucket(key)
        bucket[:] = [x for x in bucket if x[0] != key]

개념을 드러내는 최소 구현이다. 실제 Python dict는 더 정교한 충돌·resize 전략을 쓴다.

Correctness와 핵심 불변식

삽입은 h가 지정한 bucket에만 항목을 두고 기존 key는 갱신한다. 검색과 삭제도 같은 결정적 h로 같은 bucket을 찾으므로, bucket 선형 탐색이 성공하면 정확한 key이고 실패하면 table 어디에도 그 key가 없다.

Complexity

연산/사건기대최악의미
find/insert/deleteO(1+α)Θ(n)무작위 h에 대한 기대
resize—Θ(n)드물게 전체 재배치
갱신 연속분할상환 기대 O(1)한 번은 Θ(n)확률과 연산열 분석 모두 사용

MIT-style 문제

Mechanics

m=4, h(k)=k mod 4에 2,6,7,10을 chaining하고 6을 삭제하라.

Recognition

α=8인 table과 α=1인 table의 기대 검색 비용을 비교하라.

Invention

resize가 필요한 동적 hash table의 불변식과 임계값을 설계하라.

해설 보기
  1. bucket 2는 [2,6,10], bucket 3은 [7]; 삭제 뒤 [2,10].
  2. 둘 다 점근적으로 O(1)이지만 기대 chain 검사는 각각 O(9), O(2) 수준이다.
  3. 예: α>2면 두 배, α<1/4이면 절반(최소 크기 유지). 재해시 뒤 모든 x가 T[h(x.key)]에 있어야 한다.

Feynman Test

“hash table은 O(1)”이라는 문장을 worst-case, expected, amortized라는 세 단어로 정확히 고쳐 말하라.

빈 종이 테스트

direct access → hash → collision → chaining → α → universal hashing의 흐름과 확률식을 복원하라.

한 장 요약

  • Hashing은 key를 Θ(n) 크기 table 주소로 압축한다.
  • Chaining 비용은 chain 길이, 즉 α와 분포에 달렸다.
  • Universal hashing은 임의의 고정 key 집합에 대해 기대 O(1+α)를 준다.

다음 장 연결

순서 연산까지 필요하면 key의 대소 관계를 구조에 보존하는 BST가 필요하다.
